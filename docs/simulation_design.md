# 仿真设计

## 仿真核心

仿真核心只负责：

1. 接收底层飞行和武器指令；
2. 推进飞机和导弹动力学；
3. 更新实体状态；
4. 生成事件；
5. 生成 `SimulationSnapshot`。

它不负责策略训练和奖励重分配。第一版使用本地 JSBSim，但遵循 ZK 的状态、指令、时间、事件、初始化和终止语义。

## 平台 Adapter

新项目需要至少支持两种 Adapter：

```text
LocalJSBSimAdapter
ZKSocketAdapter
```

两者都应提供相同的仿真接口，使规则策略、执行层和评估工具不依赖平台细节。

## 初始化模式

### `official`

使用正式比赛或正式评估的初始化方式，用于最终性能评估。

### `combat_start`

根据官方初始化和编队运动估计接敌阶段的状态，用于减少训练中长时间无效进场样本。这个模式必须单独记录，不能混入正式评估结果。

### `custom`

使用声明式 ScenarioInitialization 覆盖任意飞机、导弹、传感器、通信、战争迷雾、武器账本、策略状态、执行状态和飞控状态。环境 reset 不能把初始化写死。

## 快照、恢复和终止

统一接口为 reset(initialization)、step(command)、snapshot()、events()、restore(snapshot) 和 termination_status()。快照必须恢复动力学、武器、感知、战争迷雾、策略 RNN、执行 RNN、飞控隐藏状态、随机数、事件和终止状态。

结束条件使用可组合 TerminationProvider，支持比赛时长、全敌摧毁、全我摧毁、安全返航、边界失败、仿真卡死、导弹超时和外部平台结束。

## 快照和事件

快照应包含飞机、导弹、传感器摘要、资源状态和规则所需的历史信息。事件至少包括：

- 目标首次探测；
- 目标丢失；
- 导弹发射请求；
- 平台发射确认；
- 命中或失效；
- 导弹告警；
- 击落或坠毁；
- 边界、高度和速度保护触发；
- 任务完成或重规划请求。
